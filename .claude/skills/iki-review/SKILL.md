# IKIDigitalLab コードレビュースキル

このスキルは IKIDigitalLab ウェブサイトプロジェクト固有のルールに基づいてコードをレビューするためのものです。

## 目的と制約

- ユーザーが指定した**特定ファイルのみ**を対象にレビューする
- **バグ・ロジックの誤りを最優先**でチェックする
- 指摘事項と修正案を提示するが、**ファイルへの変更は行わない**
- 出力はすべて**日本語**で行う

## レビュー手順

1. ユーザーが指定したファイルを読み込む
2. 下記のチェックリストに沿ってレビューする
3. 重要度別に結果を出力する

---

## チェックリスト

### 🔴 高優先度（バグ・セキュリティ・データ損失リスク）

**TypeScript**
- `any` 型の使用（型安全性の喪失）
- `null` / `undefined` の未チェック（オプショナルチェーニング漏れ）
- 型アサーション `as` の不適切な使用（実行時クラッシュの原因）

**Next.js App Router**
- `'use client'` / `'use server'` ディレクティブの付け忘れ・誤り
- Server Action での入力値未バリデーション（Zod の `safeParse` 未使用）
- `notFound()` / `redirect()` を `try-catch` 内で呼ぶと例外がキャッチされて動作しないバグ
- 環境変数を `undefined` チェックなしで使用（`process.env.XXX!` の不用意な使用）
- ISR キャッシュタグ（`tags: ['news']`）の漏れ・ミスマッチ

**microCMS**
- API キー等の認証情報のハードコード
- `.catch(notFound)` 等エラーハンドリングの欠如

**フォーム・バリデーション（Zod）**
- `formData.get()` の結果を `as string` でキャストして未検証のまま使用
- `safeParse` の失敗ケース（`!validatedData.success`）の未処理

**セキュリティ**
- Webhook の API キー検証が現在コメントアウト中（`src/app/api/revalidate/route.ts`）。この箇所に触れるPRでは意図的なものか確認を促す

### 🟡 中優先度（ロジックの誤り・潜在的バグ）

**非同期・副作用**
- `await` の付け忘れ
- `useEffect` 内のクリーンアップ関数漏れ
- `useEffect` / `useCallback` / `useMemo` の依存配列漏れ

**Next.js**
- `useRouter` / `usePathname` / `useSearchParams` を Server Component で使用
- `<Image>` の `alt` 属性・`width` / `height` 指定漏れ
- 動的ルートの `params` 型定義ミス

**ロジック**
- 条件分岐の網羅性の欠如（特にユニオン型の分岐）
- 配列・オブジェクトの意図しない破壊的変更
- 機能フラグ `getServiceUrl()` の戻り値（`null` の可能性）を未チェックで使用

**Tailwind CSS**
- テンプレートリテラルや動的文字列でクラス名を構築（Tailwind のパージで消える）

### 🟢 低優先度（コード品質・規約違反）

- Props 型に `interface` を使用（このプロジェクトは `type` に統一）
- `@/*` パスエイリアスを使わず相対パスで深くたどるインポート
- `console.log` の混入（`console.error` はサーバー側のみ可）
- コメントアウトされたコードの放置

## 出力フォーマット

以下のテンプレートに従って出力する。

```
## コードレビュー結果: `{ファイルパス}`

### 🔴 高優先度（{N}件）

#### 1. {問題のタイトル}
- **行数**: L{行番号}
- **問題**: {何が問題か、なぜ問題か}
- **修正案**:
  ```ts
  // 修正後のコード例
  ```

---

### 🟡 中優先度（{N}件）

（同様の形式）

---

### 🟢 低優先度（{N}件）

（同様の形式）

---

### 総評
{ファイル全体のまとめ。問題がない場合は「指摘なし」と明記し、特に良い点を 1〜2 点コメントする。}
```

## 注意事項

- 指摘はバグ・ロジックの誤りに絞る。一般的なスタイルの好みは低優先度にとどめる
- 修正案はそのままコピーして使えるコードスニペットで示す
- 問題がない場合は「指摘なし」と明記し、特に良い点を 1〜2 点コメントする
